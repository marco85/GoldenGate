# GoldenGate audit — October 18, 2026

Scope: repository, build history and USB identification. Original baseline: 14 configuration checks passed. Those checks mostly search strings and do not establish bootability or hardware support.

## Critical

- `goldengate-installer`, disk enumeration: fabricated `/dev/nvme0n1` after failed detection; USB/removable/read-only disks could be included. Fix: fail closed, filter transport and state, recheck immediately before partitioning.
- `goldengate-installer`, account creation: full name interpolated into root shell script. Fix: argument arrays; validate username, password, hostname and line breaks.
- `goldengate-installer`, execution: missing UEFI/image prerequisites discovered after erasure. Fix: preflight all mandatory payloads/tools and UEFI before touching target.

- Browser sharing imported removed Python `cgi`, accepted uploads even with receiving off, and overwrote existing filenames. Fix: supported multipart parser, enforce opt-in for GET/POST, cap uploads at 100 MB, create unique files exclusively, and run the browser bridge only while its window is open. Everyone mode exposes sharing to the local network and should only be used on trusted Wi-Fi.

- A local UEFI boot of the original October 18 image blocked at systemd-firstboot timezone questions. Fix: preconfigure timezone/keymap and mask terminal firstboot setup in the image. The bundled wallpaper is now explicitly applied by the desktop layout.

- Visual testing showed the incomplete custom Aurorae decoration repeating rounded titlebar tiles. Use the native Breeze decoration with controls on the left. Fix missing Plasma layout metadata and reserve the welcome assistant for the installed account; the live session opens only its hardware/install checklist.

- Full dock instantiation found the removed Plasma X11 thumbnail type and a global Kvantum override breaking Kirigami controls. Fix: icon fallback for legacy X11 previews, native KDE Qt Quick controls, and no forced global widget-style override. Add an instrumented whole-applet readiness check inside the disposable VM.

- Direct desktop installer launch previously elevated only after the user filled the form, then discarded those details. Fix: elevate before opening the form, with a regression check; remove the live installer launcher from the installed desktop menus.

## Major

- Installer silently substituted a default password, defaulted to automatic login, lacked password confirmation, and allowed window close while worker ran. Fix: explicit credentials, login default off, acknowledgement, safe confirmation default, close guard and retry.
- Live checklist marked keyboard, gestures, touchscreen and networking successful without testing. Fix: manual checks start unchecked; detection is described separately.
- Build only tested source strings and ISO size. Fix: actual filesystem inspection plus UEFI boot, full offline install and installed account login in a VM before release.
- Guide describes Calamares while the build aliases it to the custom installer. Fix: document the actual flow.
- `systemsettings` and `aurorae` were referenced without explicit packages. Fix: install both.
- Optional tools (`howdy`, emitter, LocalSend, xremap, libinput-gestures, third-party blur) are absent from the package set. Do not promise their features. Face enrollment is disabled when its tools are unavailable; password login remains standard.

## Desktop decision

Use the GPL Pear Dock, pinned with checksum and bundled source, for polished task management. Retain KDE menu/settings, fallback task manager, Surface kernel and GoldenGate theme. Use a short list of real applications, restrained magnification and no expensive refraction by default. Do not transplant the distribution-specific pearOS settings or installer.

## Verification limits

A VM cannot establish Surface touchscreen, suspend, camera, Wi-Fi, trackpad feel or graphics behavior. These require the live checklist on the actual laptop before installing. No fixed install duration or facial unlock speed is claimed.

The 16 GB target was identified as external removable USB 2.0 FD, 16,079,781,888 bytes, disk5. Device identity must be checked again immediately before writing. The 250 GB SANDISK project drive is never a target.
